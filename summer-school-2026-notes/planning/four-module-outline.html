1 Four-Module Outline

Working title: Power Laws in Data and Optimization.

1.1 Recommended Arc

The audience should leave with one organizing idea:

Power-law covariance is an observable structure of data. It persists through simple neural representation maps, and once it is present, it predicts which optimization controls matter.

The four lectures should therefore go:

  1. Data structure.
  2. Scaling consequence.
  3. Momentum control.
  4. Spectral optimizer case study.

This keeps the first lecture accessible and empirical, gives the main quadratic model before the optimizer variants, and saves muon for the end, where it can reuse the language of spectra, phases, deterministic equivalents, and Volterra equations.

1.2 Module 1: Power-Law Covariance as a Structure

Goal:

  • Make power-law covariance feel concrete, common, and usable.

80-minute lecture shape:

  • 0-10: Show spectra from CIFAR and, if available, language embeddings or activation covariances. Define the visual signature: log-log straight lines.
  • 10-20: Define covariance spectrum, effective dimension, and the exponent. Explain why the tail matters for optimization and generalization.
  • 20-35: Introduce random sketching and activation as a toy neural layer.
  • 35-50: State the preservation theorem from the random feature model: sketching plus monomial activation preserves the input exponent, up to logs.
  • 50-65: Proof flavor, not proof: Gram trick, tensor trick, Wick expansion, head-tail split.
  • 65-75: CIFAR layer experiments: random/trained MLP, CNN, ResNet.
  • 75-80: Bridge to module 2: if the spectrum survives, optimization must see it.

Website chapter shape:

  • Visual opening.
  • Definitions in a compact “spectral dictionary.”
  • Main theorem with a plain-English interpretation.
  • Proof sketch in optional expandable blocks.
  • Experiment gallery.
  • Exercises.

Figures to use:

  • CIFAR covariance eigenvalues.
  • Iterated linear sketches.
  • Tanh MLP spectra.
  • Slope across layers.
  • ResNet trained spectra.

Exercise ideas:

  • Fit a power-law exponent from a synthetic covariance spectrum.
  • Compare raw covariance and Gram-matrix eigenvalues when features exceed sample size.
  • Verify, numerically, that a random Gaussian sketch roughly preserves the spectral tail.

Proof-sketch target:

  • Explain why the kernel/tensor trick turns high-dimensional feature covariance into a more tractable Gram object.
  • Explain where logarithmic corrections enter without doing the full counting argument.

1.3 Module 2: From Spectra to Fixed-Compute Scaling Laws

Goal:

  • Show how power-law covariance becomes a solvable scaling model and produces optimization phases.

80-minute lecture shape:

  • 0-10: Recap module 1 and introduce the power-law random features model.
  • 10-25: The three parameters: data complexity, target complexity, and model size. Relate these to Chinchilla-style compute thinking.
  • 25-40: SGD dynamics on quadratic loss. Identify the four loss components: population bias, model capacity, feature embedding, and stochastic noise.
  • 40-55: RMT interlude: sample covariance, Marchenko-Pastur intuition, deterministic equivalent, and the self-consistent equation.
  • 55-65: Volterra risk equation as the compact object encoding the learning curve. Clarify that the voice-note “Voltaire” is the Volterra equation.
  • 65-75: The 4+3 phase diagram and compute-optimal model size.
  • 75-80: Bridge to module 3: phases tell us where controls might help.

Website chapter shape:

  • Start with a “nanoChinchilla” style toy scaling calculator or static diagram.
  • Present the PLRF model.
  • Give the loss decomposition and phase diagram.
  • Put the deterministic-equivalent/RMT material in a “math lens” section.
  • End with a worked compute-optimal example.

Figures to use:

  • Toy scaling law.
  • Chinchilla lines.
  • 4+3 phase diagram/scaling figure.
  • Spectrum and forcing/kernel plots.
  • Volterra-only phase figure if polished enough.

Exercise ideas:

  • Given exponents for model capacity and noise, solve for the compute-optimal parameter count.
  • Identify which phase dominates from a plotted loss decomposition.
  • Derive the Marchenko-Pastur equation in the isotropic warm-up case.

Proof-sketch target:

  • Show the pipeline: covariance spectrum -> sketched kernel resolvent -> deterministic equivalent -> forcing/kernel functions -> Volterra risk curve -> scaling exponent.

1.4 Module 3: Momentum as an Optimization Control

Goal:

  • Explain why ordinary momentum may not change scaling exponents, and why dimension/data/log-time adapted momentum can.

80-minute lecture shape:

  • 0-10: Recap module 2: scaling phases expose the bottleneck.
  • 10-25: Classical momentum and why short-memory EMA acts like SGD at scale.
  • 25-40: DANA as damped/log-time Nesterov: long memory plus stability control.
  • 40-55: PLRF theory: SGD-M versus DANA-constant/DANA-decaying scaling exponents; where outscaling is predicted.
  • 55-65: Kesten lemma or upper-bound flavor: why stability is the hard part.
  • 65-75: Translation to language models: ADANA, Ademamix correspondence, log-time beta schedules, log-time weight decay, baselining.
  • 75-80: Bridge to module 4: modern optimizers often hide spectral assumptions.

Website chapter shape:

  • Begin with a simple simulator contrasting SGD, constant momentum, and DANA.
  • Then give the scheduling principle: memory horizon grows with training time.
  • Separate “theorem world” from “production world.”
  • Include a baselining section: compute saved, learning-rate scaling, broken power laws.

Figures to use:

  • PLRF optimizer comparison.
  • Phase ODE plots.
  • DANA scaling exponents.
  • LSTM Chinchilla / effective alpha.
  • ADANA compute saved and scaling comparisons.
  • Ademamix schedules.
  • Weight-decay comparison.
  • Kappa sweep / failure modes.

Exercise ideas:

  • Compare the effective memory horizon of constant beta and beta(t) = 1 - c/t.
  • Show why a naive long-memory stochastic momentum can become unstable in a toy sparse-gradient oracle.
  • Compute a “compute saved” number from two interpolated scaling curves.

Proof-sketch target:

  • Make the stability/acceleration trade-off explicit: long memory is needed for acceleration, but stochastic noise and sparsity require damping or effective time correction.

1.5 Module 4: Muon and Spectral Optimizers

Goal:

  • Use muon as a fresh test of the framework: what does a spectral optimizer do when the covariance has a power-law tail?

80-minute lecture shape:

  • 0-10: Introduce muon as a spectral/orthogonalized update and SignSVD as a tractable proxy.
  • 10-25: Matrix-valued least squares model and comparison to SignSGD/Adam-like behavior.
  • 25-40: Exact/deterministic dynamics and the isotropic warm-up.
  • 40-55: Half-anisotropic power-law model: square-root preconditioning at large batch, SGD-like behavior in small eigenmodes at small batch.
  • 55-65: RMT interlude: deterministic equivalents, drift and volatility kernels, power-law asymptotics.
  • 65-75: Phase diagram: SignSVD favored, SignSGD favored, trade-off region.
  • 75-80: Closing synthesis across the four lectures.

Website chapter shape:

  • Start with a visual comparison of update geometry.
  • Define SignSVD and SignSGD side by side.
  • Use isotropic data as the sanity check.
  • Then show what anisotropy and power-law covariance change.
  • Close with a “what this says about optimizer design” section.

Figures to use:

  • Half-anisotropic risk and density.
  • SignSVD/SignSGD sweep.
  • Convergence rate comparison.
  • Noise floor comparison.
  • Rate versus batch.
  • ODE versus Monte Carlo comparisons.

Exercise ideas:

  • Work out the isotropic case and see why SignSVD and SignSGD match up to a constant.
  • Derive the qualitative square-root preconditioning statement from a diagonal covariance toy model.
  • Use a phase diagram to decide whether SignSVD or SignSGD should win for given alpha, beta, and batch scale.

Proof-sketch target:

  • Show how the same chain appears again: spectral update -> deterministic equivalent -> drift/volatility kernels -> power-law asymptotics -> phase diagram.

1.6 Cross-Module Threads

  • The same exponent appears in data, features, scaling laws, and optimizer schedules.
  • RMT enters as a language for replacing random high-dimensional objects by deterministic spectral equations.
  • Volterra equations are a compact way to represent learning curves.
  • The right level of math for the live lectures is “statement plus mechanism”; the website can carry the optional derivations.
